# macOS V0.1 实现与验收

## 范围

现有 React/Figma 界面保留，封装为本地 WKWebView。Swift 原生层使用 AVFoundation、Vision 和 AppKit。应用从 bundle 内加载页面，无需启动 Vite、服务器或网络连接。

- Task / Timer：沿用任务队列、圆盘时长、分段休息、暂停/继续/重置、完成任务与本地存储。完成当前任务会停止该次计时和监测。
- Task History：手动完成任务时归档标题、完成时间、累计专注秒数和分神次数，按本地日期分组展示。暂停/重置/完成/计时结束结算实际走过的专注阶段，排除休息与暂停并防止重复累计。旧存储兼容迁移；旧版已经删除的任务无法恢复。计时到点只增加一次“今日专注”计数，不自动完成任务。
- Distraction History Bridge：原生仅在 `alertVisible` 从 false 变成 true 时发出 `focus-native-distraction`，包含唯一提醒 ID、计时会话 ID、毫秒时间戳。网页按会话归属去重、忽略过期会话/暂停/休息事件后累加到当前任务；每帧、短暂回看未收起、显示器窗口重建均不重复计数。会话变更会取消旧摄像头回调。
- CameraMonitor：只在运行中的专注阶段采集；请求系统权限；优先 1280×720（不支持时回退 640×480）、分析约 7.5 FPS；丢弃过期帧。串行后台队列管理 session、帧处理和资源释放。
- VisionAnalyzer：明确指定 face rectangles revision 3；读取 pitch/yaw/roll，弧度转度；同帧执行 face landmarks 提取双眼轮廓和瞳孔；不保存图像。多脸、低置信度、极暗画面、缺失角度及推理失败均为 unknown。
- AttentionEngine：启动自动观察至少 6 秒，并取得至少 1.5 秒、8 个连续稳定样本建立相对基线，无需逐点校准。仅对附近的稳定坐姿做有界慢速适应；EMA α=0.3；转头与上下偏离连续 7 秒触发；无脸连续 9 秒触发。回正稳定 1.5 秒后退出，冷却 25 秒。回正阈值比触发阈值更窄，避免边缘抖动。roll 不单独触发。
- ReminderController：每块显示器中央显示灰绿色圆润宠物（身体约 237×213 pt，透明窗口 320×300 pt，无嘴、无四肢、无文字或背景卡片）；12 秒循环间歇眨眼、上下左右看，身体固定不跳动。透明 NSPanel、鼠标穿透、不抢焦点、跨 Space/full-screen auxiliary；回正稳定 1.5 秒后闭眼并在 0.25 秒内淡出。系统减少动态效果开启时静态显示、立即收起，且不启动动画定时器；支持显示期间切换。暂停、休息、结束或信号失效立即移除。
- FocusSessionManager：原生时钟独立检查完整计时计划，网页退到后台后仍可在休息/结束时关闭摄像头。权限回调及队列样本带有会话代次校验，暂停后的旧结果无效。8 秒无帧则关闭监测并提供重试。
- 系统睡眠、显示器休眠、关闭窗口、退出应用时停止监测并暂停计时；最小化或切到其他应用时保持专注监测。
- 设置可关闭摄像头提醒、重新适应坐姿、重试或打开系统摄像头权限页面。拒绝授权仍可计时。

0.1.4 正式提醒已加入基于 Vision landmarks 的近似视线方向，与头部并行判断。仍不做手机识别、屏幕内容分析、模型训练、LLM 或云端推理。网页仅收取状态码/提示文案，不接触摄像头原始画面。

0.1.3 在设置和原生「专注」菜单增加只读「监测诊断」。它显示正式监测当前角度、坐姿基准、平滑后的相对偏离、连续计时、冷却剩余时间，以及 Vision 人脸数量/置信度和不可用原因。打开窗口不会启动第二路摄像头、暂停专注或改变基线；暂停/结束/断流后清除过期数值。数值只留内存，不自动保存日志。疑似偏离期间主界面显示「正在确认偏离」，不再笼统显示「本地监测中」。

诊断还显示眼部基准/有效性、双眼相对瞳孔偏移、噪声门限、有效视线累计时长以及触发来源。此工具用于定位真实漏判，不能把合成角度/点位测试等同于实际视线识别。眼镜反光、头部姿态、眼睑变化或瞳孔偏移小于噪声时仍可能漏判。

0.1.1 另加主动开启的 [眼动测试窗口](eye-test.md)，使用眼部 landmarks 做近似方向实验；与正式监测独立；测试窗口的人工采样不会覆盖正式监测基准。测试可在专注之外开启，会暂停专注，并在关闭测试或退出时释放摄像头。

## 头部与视线融合

- 自动观察期间，在当前稳定头姿下收集最近 2.5 秒的双眼样本。至少 10 个样本、跨度 ≥1.5 秒，双眼各轴标准差 ≤0.05 才建立眼部基准。短暂眨眼可跳过；基准不足仍正常进行头部监测，不在后续低头过程中偷偷学习新眼部基准。
- 归一化瞳孔 y 向下；双眼分别减去自己的基准，再 EMA（0.35）。两眼必须同时超过阈值：y 为 max(0.08, 3×基准噪声)，x 为 max(0.10, 3×基准噪声)。回正门限为触发门限的 60%。这只是几何启发式，不是精确屏幕注视点。
- 眼部只在相对初始头姿 pitch ≤12°、yaw ≤20°、roll 变化 <15° 时参与；大幅转头交给头部规则，减少透视变化造成的瞳孔误判。
- 明显头部偏离持续 7 秒，或双眼同方向偏离有效累计 10 秒，任一满足可提醒；两路时长不互相借用。上下及左右方向均支持，不能区分屏幕边缘、键盘与手机。
- 眼部丢失 ≤0.6 秒暂停累计（不计算未知时段），恢复后可继续；超过 0.6 秒清空视线连续证据。至少 80% 的这段时间为有效偏离证据才可触发。双眼矛盾、眨眼闭合、反光导致的缺点等不能单独触发。
- 已有视线提醒时，头部与有效视线均回正才累计 1.5 秒收起；眼部长期丢失而头部正常时撤下眼部提醒，原因是不确定，不宣称用户已回正。头部独立提醒仍可在眼部不可用时根据头姿收起。共用 25 秒提醒冷却。
- 没有添加键盘/鼠标监听，不读取输入内容。持续看键盘、纸面资料也可能提醒；它不是手机检测。

## 默认参数

参数集中于 `macos/Sources/FocusCore/AttentionEngine.swift` 的 AttentionConfig。

| 项目 | 默认值 |
|---|---|
| 启动自动适应 | 连续有效观察至少 6 秒；当前姿态稳定至少 1.5 秒、8 帧，波动不超过 8° |
| 小幅坐姿适应 | 原始角度在当前基线 pitch ±6° / yaw ±8° 内，稳定 10 秒（极差 ≤3°）；20 秒时间常数慢速更新 |
| 适应范围 | 相对最初基线最多 ±4°，不会无限跟随持续偏头；无效、无人、偏离及提醒期间中断适应 |
| 左右偏离 | 相对基线 >30°，持续 7 秒 |
| 上下偏离 | 相对基线 >18°，持续 7 秒；基于已有低头反馈调整，尚需真实摄像头误报验证 |
| 视线偏离 | 双眼同向超过噪声门限，有效累计 10 秒；未知时段不计入 |
| 未见人脸 | 3 秒疑似；9 秒 Away |
| 回正 | yaw <22° 且 pitch <12°，持续 1.5 秒 |
| 冷却 | 25 秒 |
| 推理 | 约 7.5 次/秒 |
| 数据中断 | >1 秒重置连续证据；>8 秒停止并提示重试 |

默认正常开始任务即可，计时不等待自动适应。启动观察期可以避开开始时约 1～2 秒的低头，但头部角度不能证明用户正在看屏幕：如果整个观察期一直低头，仍可能建立错误基线。此时面向工作屏幕，使用可选的“重新适应坐姿”纠错。基线仅在当前监测段内存中保存，暂停、休息、重启或主动重置后重新观察。

不读取屏幕铰链角度，也不把任意新姿势自动认作正确姿势。换屏、明显调整屏幕开合角度或摄像头位置后若提醒不准，使用“重新适应坐姿”；有界自动适应只覆盖小幅变化。外接摄像头按驱动提供的正常安装方向处理；macOS 14+ 使用 RotationCoordinator 修正输出帧方向。物理倒装且不报告方向的外置摄像头不属于本版验证范围。

## 自动验证

```sh
npm test              # 原有界面 + 原生桥接契约（Playwright / Chrome）
npm run test:native   # 纯 Swift 状态机与原生计时计划，无需 XCTest / 完整 Xcode
npm run mac:build     # 类型检查、生产构建、Swift 编译、app 打包和本地签名校验
npm run test:mac      # 运行真正的 WKWebView / Vision / AppKit 集成测试；不申请摄像头权限
```

原生集成测试验证：bundle 页面加载、本地存储、JS→Swift 完整计划同步、原生暂停→React 持久化、实际 Vision 处理明暗无脸像素缓冲、校准→提醒→自动消失，以及真实窗口的鼠标穿透/非激活配置。还使用受控摄像头替身验证延迟授权、权限拒绝、暂停后迟到样本、跨会话回调、断流重试、原生阶段切换与退出后拒绝重启。摄像头帧以外的头部姿态序列在测试中为合成数据，不代表真实头部识别准确度。

新增原生集成测试还覆盖自动眼部基准、头部不变时视线触发真实宠物窗口，以及双信号回正收起。

宠物集成测试还覆盖居中尺寸、实际 key/main 窗口不变、四方向与眨眼循环、重复触发不重建、淡出期间重新显示的竞态，以及收起后停止动画并释放窗口。

报告和截图：`artifacts/native-smoke/result.json`、`native-window.png`、`pet-overlay.png`、`pet-states.png`（居中、左、右、上、下、眨眼）。测试模式使用临时 WebKit 数据存储，不改变日常使用的任务和摄像头偏好。

## 真实摄像头验收（仍需实机使用）

1. 打开 app；未开始时系统摄像头指示灯不亮。
2. 开始专注并允许权限，正常使用约 6 秒，状态从“自动适应中”变为“本地监测中”。另测开始时低头 2 秒再回屏幕，应采用后来的稳定姿势。
3. 短暂低头/转头 1～3 秒不显示宠物；明显侧头保持约 8～10 秒，出现宠物。
4. 回正约 2 秒自动消失；立刻再次侧头不应在冷却期内反复提醒。
5. 离开画面约 10 秒出现宠物；回来自动消失。遮住摄像头变暗时显示无法判断，不应当作离席。
6. 在其他 app、全屏、不同 Space 和外接屏上确认能看到眼睛，仍能正常点击和输入。
7. 暂停、休息、结束、关窗口或退出后，摄像头停止且浮层消失。拒绝授权、断开摄像头后计时仍可使用。
8. 持续使用 20～30 分钟检查误报、CPU、能耗。头部朝向无法判断“看屏幕刷视频”和“低头读资料”，按实际任务决定是否开启提醒。
9. 戴眼镜、摘眼镜、不同屏幕开合角度分别验证；在诊断中确认眼部基准有效，头部基本不动时向下看 12～15 秒，观察是否累计视线并触发。持续低头约 10 秒应有提醒，短暂看键盘不应提醒。小幅调整坐姿后应能稳定使用；明显改变机位后验证“重新适应坐姿”可纠正基线。合成角度测试不等于这些实机条件已经通过。

## 打包约束

构建使用本机 Swift/Command Line Tools，支持 macOS 13+，产物架构为当前构建机器架构。默认 ad-hoc 本地签名，带 Hardened Runtime 与 camera entitlement；尚未进行 Developer ID 签名、公证或通用架构分发。可通过 `FOCUS_SIGN_IDENTITY` 指定自己的签名身份。重新构建后 macOS 可能重新请求摄像头权限。
