# 眼动测试与正式视线融合（0.1.4）

独立眼动测试窗口用于验证「正视与低头看键盘，能否从 Vision 的眼部点位区分」，窗口本身不触发提醒。0.1.4 已把同源眼部几何接入正式监测：自动建立双眼基准，结合头部和时间规则触发提醒。接入规则不代表真实低头漏判已经解决，实际点位必须能区分这两种姿势。

## 使用

1. 退出旧版，重新打开 `build/Focus On.app`。
2. 设置 → **眼动测试（实验）**，或菜单 **专注 → 眼动测试…**。
3. 点 **开始测试**。正在进行的专注会暂停；摄像头只做本地分析。
4. 点 **屏幕中央**，两秒准备后，保持看中央约 2.5 秒，完成基线采样。
5. 依次采样顶部、底部、键盘、左边、右边。每个目标都提供两秒准备时间，按提示保持视线。
6. 重点看底部「键盘相对中央 Δy」和差异结论。重复测试 2～3 次，并注意 pitch/yaw 是否变化。

窗口显示头部角度、双眼轮廓示意、眼内归一化瞳孔 x/y、估计方向，以及每个目标的均值和波动。示意图不是摄像头预览；所有采样数据仅保存在内存。停止后保留汇总以便比较；重新开始、清空或关闭窗口会删除汇总。

没有点位、眨眼/眼睛过小、极暗、多人、双眼估计不一致等情况显示无法判断，**不会用 0 代替缺失值**。重新开始测试需要重新校准。关闭测试窗口、暂停菜单、休眠或退出 app 都停止测试；恢复专注时先关闭测试摄像头。

## 如何理解结果

- 坐标经眼角轴校正头部平面旋转；x 向未镜像的图像右方增加，y 向下增加。
- 方向按本人的左右显示；基于中央基线的差值、EMA 平滑与 0.4 秒稳定时间，属于启发式估计。
- 垂直差异超过 `max(0.08, 3 × 两组最大标准差)` 且两组采样稳定，才提示「本次信号有可分差异」。这只是本次样本的检查，不是统计准确率或临床眼动测量。
- 眼部归一化坐标仍受眼睑、眼镜、光线和头部三维姿态影响。可能无法区分屏幕底部与键盘；没有足够差异时不会声称识别成功。
- 尚未添加全局键盘监听，也没有扩大输入监控权限。是否需要结合键盘活动，待眼部信号可用性验证后再决定。

## 技术与验证

正式监测和眼动测试均使用 face rectangles revision 3，优先采集 1280×720（不支持时回退 640×480），分析频率上限约 7.5 FPS。两者都额外运行 `VNDetectFaceLandmarksRequest`，复用同一帧的人脸 observation，读取 leftEye/rightEye/leftPupil/rightPupil。按人脸框和图像尺寸恢复实际像素比例后，再投影到眼睛局部坐标。

`EyeGeometry`、`GazeReference` 和 `GazeEstimator` 位于 `macos/Sources/FocusCore/EyeTracking.swift`，纯 Swift 场景测试覆盖坐标、缩放、旋转、眨眼、缺失值、双眼一致性、基线、方向稳定和噪声比较，；正式融合由 `AttentionGaze.swift` 实现，验证头部不动时视线也能触发提醒、短暂眨眼暂停累计、长期丢失回退、噪声基准拒绝、冷却及视线回正。

- `npm run test:native`：核心规则。
- `npm test`：设置入口与桥接回归。
- `npm run mac:build && npm run test:mac`：原生窗口/图形/生命周期验证，使用合成点位而非真实用户图像。
- 实机下的瞳孔可靠性与中央/键盘可分性仍需用户使用此窗口测试。

[Apple：Face Landmarks 的坐标系](https://developer.apple.com/documentation/vision/vnfacelandmarks2d)；[Apple：眨眼会影响 pupil 的准确性](https://developer.apple.com/documentation/vision/vnfacelandmarks2d/leftpupil)。
