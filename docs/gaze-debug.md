# 在 VS Code 查看实时眼部标记

在 VS Code 打开整个 `focus-on` 文件夹，终端运行：

```sh
npm run gaze:debug
```

也可使用 **终端 → 运行任务 → Focus On: 实时视线调试**。

只需要现有的 macOS Swift Command Line Tools 和 Node/npm，不需要 Python、下载模型或完整 Xcode。命令会编译并打开独立的 `build/Focus On Gaze Debug.app`，窗口不嵌在 VS Code 编辑区内。

1. 先暂停正式 Focus On 和 App 内的眼动测试，避免同时采集、重复提醒或摄像头争用。
2. 点击 **开始摄像头**；首次允许 `Focus On Gaze Debug` 的摄像头权限。
3. 默认直接显示画面与原始点位，不需要先建立视线基准。正常看屏幕约 6 秒后，右侧才开始显示相对视线判断。
4. 勾选 **放大眼部**，分别尝试看屏幕、看键盘和看手机：观察红十字是否跟着瞳孔移动，以及轮廓是否贴着眼睑。
5. **显示标记** 可切换叠加层，方便比较原画面；**重新建立基准** 只重置该调试工具。
6. 点击 **停止摄像头** 清空画面与基准；关闭窗口或 ⌘Q 退出并释放摄像头。终端 Ctrl+C 只结束等待命令，窗口可能仍在运行，应使用窗口停止/退出。

## 图中是什么

- 黄色框：Vision 返回的人脸框。
- 绿色/蓝色线及小点：左眼/右眼轮廓关键点（`leftEye` / `rightEye`），接近眼睑开口边界，**不是眼眶骨、整个眼球或虹膜的分割轮廓**。
- 红色十字：`leftPupil` / `rightPupil` 的原始位置估计。没有点位时不画十字，不用眼睛中心代替。
- 橙色轮廓及「未采信」：Vision 有原始点，但眼部几何或关键点置信度未通过正式处理的检查。即使画出了点，也不代表融合规则一定采信；以右侧眼部状态为准。
- 画面未镜像；左/右标注沿用 Vision 的命名。

画面和叠加标记取自**同一分析帧**（上限约 7.5 FPS），不把实时预览与延迟点位混在一起。放大采用相同裁剪坐标变换。基础头部和瞳孔规则与正式 App 同源，调试工具另有下面的眼睑辅助实验，不会显示宠物提醒。眼部基准只存在该工具本次运行的内存中。

## 眼睑辅助实验

调试窗口默认勾选 **眼睑辅助（实验）**，正式 App 默认关闭。开关切换后重新采样约 6 秒。保留现有瞳孔判断，左右方向仍优先使用瞳孔；当双眼瞳孔偏移都未越过阈值时，才尝试用开合度补充上下方向：

- 开合度 = 去除平面倾斜后的眼睛高度 ÷ 眼睛宽度；左右眼各自建立固定基准。
- 开合变化 = 当前平滑后的开合度 ÷ 基准开合度 − 1。
- 双眼均缩小超过 20% → 疑似向下；双眼均增大超过 20% → 疑似向上。阈值也须高于各自基准噪声的 3 倍。
- 必须连续保持 0.8 秒；恢复正常、方向改变或点位丢失会中断候选计时，短暂眨眼不能拼接累计。接近闭眼（低于基准的一半）不作为眼睑方向信号。
- 仍受原有头部姿态、点位质量检查约束。基准开合波动太大时停用辅助，瞳孔判断保留。

右侧显示当前高/宽、基准、变化百分比和阈值；采用辅助结果时眼部状态标注“眼睑辅助”。建议头部尽量不动，分别看上、看下、自然眨眼、主动眯眼测试。**持续眯眼或刻意睁大眼仍可能误判**，持续时间过滤只能排除短暂变化，不能证明真实目光方向。

暂停判断时会区分“点位缺失”“头部角度超出参考范围”“双眼测量差异过大”“开合度低于基准一半”等具体原因。这些是算法的信号检查结果，不代表确认闭眼；信号恢复后自动继续，缺失期间不累计方向证据。

眼睑与垂直眼动的关联可参考 [Becker & Fuchs 的研究](https://pubmed.ncbi.nlm.nih.gov/3193155/) 和 [向下看时眼睑开口形态的研究](https://pubmed.ncbi.nlm.nih.gov/17041316/)。20% 与 0.8 秒是本工具的实验参数，并非这些研究验证的通用分类阈值。

## 代码入口

| 文件 | 用途 |
|---|---|
| `macos/Sources/FocusVision/CameraMonitor.swift` | 正式 App 与调试器共享的 AVFoundation 采集、Vision 眼睛/瞳孔点位提取；`imagePoints` 将人脸内归一化点转换成整帧归一化点 |
| `macos/Sources/FocusGazeDebug/PreviewView.swift` | `FrameMapping` 处理缩放/黑边/放大，`drawEye` 绘制轮廓和红十字 |
| `macos/Sources/FocusGazeDebug/main.swift` | 独立窗口、权限、同帧渲染、开始/停止和状态显示 |
| `macos/Sources/FocusCore/EyeTracking.swift` | 将原始眼部点位转换成相对眼睛坐标 |
| `macos/Sources/FocusCore/AttentionGaze.swift` | 双眼基准、噪声过滤和近似视线方向 |
| `macos/Sources/FocusCore/EyelidGaze.swift` | 眼睑开合变化、连续时间过滤和实验参数 |
| `macos/Sources/FocusCore/AttentionEngine.swift` | 头部和视线信号结合、持续时间与提醒规则 |

可以直接在 VS Code 查看/修改这些 Swift 文件，再运行同一条命令。VS Code 编辑器断点调试另需 Swift 调试扩展；运行和查看画面不需要扩展。

## 验证与隐私

`npm run test:gaze-debug` 用合成眼睛图形验证原图与标记的坐标一致性、放大、停止后清空；测试不申请摄像头权限。合成图截图保存在 `artifacts/gaze-debug/`。

正常运行只把视频帧用于当前内存预览，不录像、不保存照片、不上传。关闭窗口、退出、系统或显示器休眠会停止摄像头。断流时清掉旧画面，避免误把静止旧画面当实时追踪。
